一、AI Coding 开发原则

本项目采用 AI Coding 模式（Kimi Code / Cursor / Copilot Workspace 等），与传 统人工开发相比有以下特性，任务拆分必须适配：

特性对任务拆分的要求具体做法
上下文窗口有限每个任务的上下文必须自包含每个任务附带"上下文包"：相关 PRD 章节 + 数据模型 + 接口契约 + 现有代码引用
擅长小步迭代任务粒度 ≤ 一个会话能完成单任务 ≤ 200 行核心代码 / ≤ 2 小时 AI 生成量；大功能拆成"模型→迁移→服务→接口→页面"5 步
容易"看着对、其实错"测试必须前置且可机械校验每个任务带 acceptance criteria（API 响应示例 / SQL 校验 / 页面截图点）
风格易漂移强结构化约定 + 复用现有模板复制招聘系统的目录结构、ESLint 配置、Prisma 模板、Vue 组件库
不擅长跨文件一致性显式声明依赖关系每个任务标注"前置任务"和"被依赖任务"，避免并行冲突
对领域规则易遗漏业务规则显式化、配置化薪酬/绩效/考勤规则全部走配置表，不写死在代码里
重构能力强先跑通再优化，不一开始追求完美一期先垂直切片（一个模块端到端跑通）再横向扩展

阶段周期核心目标交付物

M2 考勤假勤第 5-7 周模块 B 完整落地打卡 + 排班 + 请假/加班/出差 + 月度汇总可用
M3 绩效管理第 8-10 周模块 D 完整落地KPI+OKR 考核 + 系数配置 + 五档评分可用
M4 薪酬核算第 11-14 周模块 C 完整落地自动核算 + 社保三地 + 个税 + 工资条可用

总计 17 周（含 2 周并行试运行）。M3 绩效在 M4 薪酬之前，因为薪酬依赖绩效系数。

2.2 垂直切片策略（关键）

不采用"先全部后端再全部前端"的横向切法，而是按垂直切片（每个切片包含 模型→API→页面 完整链路）：

  • 每个切片独立可演示、可测试
  • AI 单次会话能完成一个切片
  • 失败影响面小，回滚成本低
  • 早期就能让 HR 看到真东西，及时纠偏

9.2 上下文管理

  • 项目级：维护 AGENTS.md 在项目根，描述项目结构、技术栈、命名规范、参考项目路径
  • 模块级：每个模块目录下放 README.md，说明本模块的业务规则与依赖
  • 任务级：每个任务的 Prompt 显式列出"需要读哪些文件"，不让 AI 自己猜

9.3 代码评审

AI 生成的代码必须经人工评审，重点检查：

  • 业务规则是否漏掉（如"超过 3 天请假要总经理审批"）
  • 边界条件是否处理（空值、并发、事务）
  • 敏感字段是否加密（身份证、银行卡、薪资）
  • 审计日志是否记录（增删改操作）
  • SQL 注入 / XSS / CSRF 风险
