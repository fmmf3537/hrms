# HRMS AI 知识库冷启动内容

> **范围**：M0.5-5 AI 底座上线时的知识库初始内容
> **关联文档**：[`HRMS-V1.2.md`](./HRMS-V1.2.md) §四.4.1 M0.5-5 验收（已交叉引用本文档） · §六.5 启动清单
> **V1.2.1 新增**：为 AI 智能问答（`POST / /ai/qa`）提供首日可用内容，避免冷启动尴尬

## 一、为什么需要冷启动内容

M0.5-5 上线后 AI 智能问答（`POST / /ai/qa`）需要 RAG 检索命中才能给出基于公司实际制度的回答。若知识库空，员工问"年假怎么请" → AI 答不出 → **首日用户体验差，对项目信心打击大**。

## 二、冷启动内容清单（M0.5-5 上线前必须就位）

| 类别 | 内容 | 来源 | 优先级 | 维护人 |
|---|---|---|---|---|
| **员工手册** | HR 版 / 部门负责人版 / 员工版 3 份 | HR 起草，IT 入库 | P0 | HR |
| **假期政策** | 年假 / 病假 / 调休 / 加班 / 婚产 / 陪产 / 丧假细则 | HR | P0 | HR |
| **工资条说明** | 应发 / 应扣 / 个税明细解读 + 常见疑问 | HR + 财务 | P0 | 财务 |
| **报销流程** | 出差 / 差旅补助 / 借款还款 SOP | HR + 财务 | P1 | 财务 |
| **FAQ** | HR 答疑高频问题 ≥ 20 条 | HR | P0 | HR |

合计入库文档 ≥ 28 份（含 3 份员工手册 + 7 类假期 + 1 工资条 + 3 报销 + 20 FAQ = 34 份）。

## 三、内容来源规范

1. **优先复用现有制度文档**：辰航已有的《员工手册》《绩效考核办法》等直接 PDF / Word 入库
2. **缺失内容由 HR + AI 协作**：HR 列业务场景 + 关键问答，AI 格式化 / 拆分 / 入库
3. **统一元数据**：每篇文档带 `source_type`（employee_handbook / faq / policy）、 / `category`（attendance / salary / leave / reimbursement）、 / `tags`（便于 RAG 检索分类）

## 四、AI 回答边界（必须告知员工）

知识库冷启动后，AI 仅回答**上述 28+ 篇文档覆盖范围内**的问题：
- ✅ "我还有几天年假？"（基于假期政策 + 用户实际余额动态计算）
- ✅ "工资条怎么看？"（基于工资条说明）
- ✅ "差旅补助怎么算？"（基于报销流程）
- ❌ "公司战略是什么？"（不在知识库 → AI 应答"该问题暂不在 AI 知识范围，建议咨询 HR"）
- ❌ "我同事工资多少？"（合规边界，AI 直接拒绝）

**降级策略**：AI 置信度 < 0.7 或命中知识库无关 → 自动建议"转人工 HR"，并附 FAQ 链接。

## 五、初始化 SQL 脚本

放在 `server/prisma/seed-ai-knowledge.ts`，由 M0.5-5 切片产出：

```typescript
// 示例：知识库初始化结构
const docs = [
  {
    title: '员工手册（员工版）',
    sourceType: 'employee_handbook',
    category: 'general',
    content: '...', // HR 提供的完整文本
    chunks: splitIntoChunks(content, { chunkSize: 500, overlap: 50 }),
  },
  // ... 共 34 篇
];
for (const doc of docs) {
  await prisma.aiDocument.create({ data: doc });
  // M0.5-5 同步：每 chunk 生成 embedding 写入 ai_embeddings
}
```

## 六、运营机制（V1.2 后）

- **每周**：HR 收集员工未命中 AI 的问题，补充 FAQ → 重新入库
- **每月**：分析 `ai_conversations` 中置信度 < 0.7 的对话，识别知识缺口
- **每季度**：法务 / HR 联合 review 知识库内容合规性（防止过期政策仍被检索）
