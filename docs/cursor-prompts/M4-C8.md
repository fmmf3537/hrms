### 4.1 子任务 8.1：调薪申请（salary_adjustment.service.ts createAdjustment / submitAdjustment）

**1 新表**（`salary_adjustments`）

**Service 函数**：
- `createAdjustment(actorId, input)` — 创建调薪申请（status='draft'，4 种类型）
- `submitAdjustment(actorId, id, input?)` — 提交审批（status='draft' → 'pending'，调 M0.5-1 approval）

**算法**（createAdjustment）：
1. 校验 employeeId 存在（`prisma.employee.findUnique`）→ 不存在抛 73804
2. 校验 employee.status === 'active'（不允许已离职员工）→ 否则抛 73804
3. 校验 currentBaseSalary（`prisma.employee_salary_plans` 当前 active plan 的 baseSalary）→ 不存在抛 73804
4. 校验 newBaseSalary > currentBaseSalary（**C8 不实现减薪流程**）→ 否则抛 73806
5. 计算 increaseRatio = (newBaseSalary - currentBaseSalary) / currentBaseSalary
6. 校验 increaseRatio 范围 [min_increase_ratio, max_increase_ratio]（默认 [0.05, 0.30]）→ 越界抛 73806
7. 校验 effective_date 格式 + 提前通知天数（effective_date - now() ≥ advance_notice_days 默认 7）→ 否则抛 73805
8. 校验同一员工 effective_date 已有 pending / approved / executed 调薪（`prisma.salary_adjustments.findFirst`）→ 否则抛 73809
9. 校验 adjustmentType ∈ ['promotion', 'annual_adjust', 'performance', 'market_adjustment']
10. 事务：create `salary_adjustments`（status='draft'，approvalInstanceId=null）
11. 写 audit（SALARY_ADJUSTMENT_CREATE，actorType='USER'）

**算法**（submitAdjustment）：
1. 查询 adjustment → 不存在抛 73801
2. 状态检查：status === 'draft' → 否则抛 73802
3. 计算 require_ceo_approval = (newBaseSalary - currentBaseSalary) > require_approval_threshold（默认 5000 元）
4. 调 `approvalService.submitApproval({ flowKey: 'salary_adjustment', businessId, data, requireCeo: require_ceo_approval })` → 创建审批实例
5. update { status: 'pending', approvalInstanceId }
6. 写 audit（SALARY_ADJUSTMENT_SUBMIT，actorType='USER'）

**完整 schema + JSDoc + 错误码触发条件 + 测试断言**：见 §5.2。

### 4.2 子任务 8.2：调薪审批（salary_adjustment.service.ts approveAdjustment）

**0 新表**（更新 `salary_adjustments.status` + M0.5-1 approval 流程）

**Service 函数**：
- `approveAdjustment(actorId, id, input)` — 审批调薪（status='pending' → 'approved'，通过 M0.5-1 approval）

**算法**：
1. 查询 adjustment（含 approvalInstanceId）→ 不存在抛 73801
2. 状态检查：status === 'pending' → 否则抛 73802

### 4.3 子任务 8.3：调薪执行（salary_adjustment_execute.service.ts）

**0 新表**（写入 `employee_salary_history` + 同步 `employee_salary_plans` + 联动 `employee_position_history`）

**Service 函数**：
- `executeAdjustment(actorId, id)` — 单条执行（status='approved' + effective_date <= today → 'executed'）
- `executePendingAdjustments(actorId, asOfDate)` — 批量执行（扫描所有 approved + effective_date <= asOfDate）

**算法**（executeAdjustment）：
1. 查询 adjustment（含 employee + currentPlan）→ 不存在抛 73801
2. 状态检查：status === 'approved' → 否则抛 73802 / 73803
3. 校验 effective_date <= today（**未到生效日不能执行**）→ 否则抛 73805
4. 校验 execute_mode（configs.salary.adjustment.execute_mode 默认 'manual'，**auto 模式留 BullMQ 调度**）
5. **事务**（**rollback on error**）：
   - **写 M1 employee_salary_history**（changeType = adjustmentType 映射 + baseSalary = newBaseSalary + performanceSalary = newPerformanceSalary + totalSalary = newBaseSalary + newPerformanceSalary + effectiveDate + reason + operatorId）
   - **同步 C1 employee_salary_plans**：旧 plan `update { effectiveTo: newPlan.effectiveFrom - 1 day }` + 新 plan `create { employeeId, gradeId, levelId, baseSalary, performanceBase, allowance, welfare, effectiveFrom, status: 'active' }`
   - **联动 M1 employee_position_history**（仅 promotion 类型 + position_change_link=true）：`create { employeeId, fromPosition, toPosition, changeType: 'promote', changeDate, reason, operatorId }`
   - update `salary_adjustments.status = 'executed'` + executedAt + executedBy
6. 触发通知：`notificationService.sendNotification({ type: 'email', template: 'salary_adjustment_executed', data, bypassTemplate: true })`
7. 写 audit（SALARY_ADJUSTMENT_EXECUTE，actorType='USER'，details: { adjustmentId, employeeId, oldBaseSalary, newBaseSalary, changeType, effectiveDate }）
8. **失败回滚**：事务失败时所有写入 rollback，update `salary_adjustments.status = 'approved'`（保持原状态）

**算法**（executePendingAdjustments）：
1. 校验 asOfDate 格式（YYYY-MM-DD）→ 否则抛 73805
2. 查 `salary_adjustments`（status='approved' + effective_date <= asOfDate）
3. 循环调 `executeAdjustment(actorId, id)`（**单条失败不中断，记录失败原因**）
4. 返回 `{ totalCount, successCount, failedCount, results: [{ adjustmentId, status, error? }] }`
5. 写 audit（SALARY_ADJUSTMENT_EXECUTE，actorType='USER'/'SYSTEM'，details: { batchMode: true, totalCount, successCount, failedCount, asOfDate }）

**完整 JSDoc + 错误码触发条件 + 测试断言**：见 §5.4。

/**
 * 实际执行调薪（status='approved' + effective_date <= today → 'executed'，写 employee_salary_history + 同步 employee_salary_plans）
 * @param actorId 操作人 ID（hr/admin/executive）
