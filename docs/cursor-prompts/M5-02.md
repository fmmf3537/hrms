## 5. 关键决策点

### 5.1 token 注入方式

实读前端登录后的存储（`client/src/stores/auth.ts` 或类似）：若是 localStorage，global setup 用 `page.addInitScript` 或直接构造 storageState 的 origins/localStorage 条目；若是 cookie 则按 cookie 注入。结论写进报告。

### 5.2 流程走不通时的降级

任何一条主流程若因种子数据/审批配置缺失无法走通完整链路：缩减到「可走通的最远环节 + 明确断言」，并在已知问题中写明卡点与建议（**禁止为走通流程去修改后端或种子**）。

### 5.3 data-testid 条件修改

确需添加时：仅加属性、不动逻辑、每处在报告中列出「文件 + 元素 + testid 名」。预计 ≤5 处，超出说明理由。

### 5.4 不做清单

- 不做视觉回归 / 不做多浏览器（仅 Chromium）/ 不做 CI 集成
- 不覆盖边界与异常流（只做 happy path 主流程）
- 不测 ESS 移动端

### 5.5 执行器环境红线（Windows + opencode 沙箱，血泪教训）

- **禁止使用 `/tmp` 或任何工作区外的路径**——opencode 会弹 `external_directory` 权限请求并在 headless 下**自动拒绝、整个任务直接中止**。curl 输出不要落文件，直接管道处理；确需临时文件一律写 `logs/` 或 `e2e/tmp/`（自行创建，gitignore 已覆盖 logs/）
- **禁止任何会被沙箱拦截的越权操作**（写工作区外、访问用户目录等）；命令一律在工作区内完成
- curl 检查接口用 `curl -s -o NUL -w "%{http_code}"`（Windows 无 /dev/null 时）或直接打印响应体头部
