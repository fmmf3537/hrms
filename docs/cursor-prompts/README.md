## 强约束条款（所有 Cursor 任务必须包含）

每条提示词都必须在"必读约束"段顶部包含以下内容：

```text
⚠️ 强约束（最优先阅读）

历史教训：M0.5-5 任务中，Cursor 越界做了 M0.5-6（配置中心）+ M0.5-7（改密 + 2FA）共 2 个不在提示词范围内的切片，并修改了 4 个旧测试文件 + 在报告中虚假陈述"原有用例未改"。本次任务严禁重蹈覆辙。

红线（违反任何一条 → 任务失败，需回退重做）：

1. 禁止越界做其他切片：本提示词只授权"X 切片"。严禁自作主张做 Y、Z 等。
2. 禁止修改未授权文件：清单以外的文件全部禁止改动。
3. 禁止修改旧测试文件：本任务完全不需要改任何测试。如果发现"必须改测试才能跑通"的情况，立即停下，说明原因。
4. 必须报告完整：交付报告必须列出全部新增/修改文件（即使是 0 个也要说"0 个"）。
5. 禁止"我觉得这也有用"：任何"顺便做"或"我觉得可以优化"的越界内容一律禁止。
```

## 提示词优化理念

**简化 ≠ 优化**。A6 第一次"瘦身 53%"是错误方向；用户指出后反向优化回 45KB，234/234 通过 + 0 越界。

| 模式 | 效果 |
|---|---|
| 简化提示词（15KB） | Cursor 推断/补全消耗大量 token，返工风险高 |
| **详尽提示词（45KB）** | **关键决策点全部锁死，Cursor 一次到位，token 反而少** |

**详尽 = 优化**。所有后续 Cursor 提示词都按 45KB 量级写，关键决策点（schema 完整定义 / 函数参数 + 校验链 / 错误码触发条件 / 测试断言细节）必须详尽；样板内容（Zod/controller/routes 风格）**引用前切片**避免重复。

## 提示词模板结构

每条 Cursor 任务提示词应包含以下段：

1. **强约束**（顶部，红线条款 + 历史教训）
2. **任务 ID + 目标**
3. **上下文**（项目位置、相关文档、当前状态）
4. **必读约束**（代码范式、错误码、审计、配置等强约束）
5. **实施任务**（明确步骤，每步指明改哪些文件、做什么）
6. **修改文件清单**（明示"清单以内可改，清单以外禁止"）
7. **验收标准**（含"原有用例未改"硬要求）
8. **禁止做的事**（额外禁忌清单）
9. **完成标准**（跑哪些命令 + 附什么交付物）
