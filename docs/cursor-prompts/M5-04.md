### 加固 2/2（commit c001273）

| 发现 | 级别 | 修复 |
|---|---|---|
| **Access token 不校验 tokenVersion**：改密/强制改密只吊销 refresh，旧 access 仍有 15min 完整权限（"全端下线"未闭环） | **高** | `authenticate` verify 后 DB 对齐 tokenVersion/status/deletedAt，不符 401 `10113 TOKEN_REVOKED`（每请求 1 次 PK 查询 <1ms） |
| 2FA 验证码 `Math.random()` 非 CSPRNG + 无尝试计数 + verify 无限流 | 中 | `crypto.randomInt` + Redis INCR 5 次错锁 30min（`10131 TWO_FACTOR_LOCKED`）+ request/verify 独立限流 |
| 登录 timing oracle：用户不存在路径不跑 bcrypt，侧信道可枚举账号 | 低 | 用户不存在也执行假 bcrypt.compare（cost12）抹平耗时 |
| 依赖 3 moderate：uuid@9 buffer 越界、qs@6.15.3（express 传递）array-limit bypass + isBuffer DoS | 中 | uuid 9→11.1.1 + pnpm override qs 6.16.0（audit 归零） |
| **审计日志明文入库**（audit-masking.md 策略未落地）：调用侧自行传值，DB 物理泄露即批量敏感数据泄露；reveal 契约存在但代码缺失 | 高（数据面） | auditLog 写入前敏感字段自动 AES 加密 `{__enc}`；列表返回解密打码（身份证/银行卡/薪资整百区间/密码 REDACTED）；新增 `POST /audit-logs/:id/reveal`（admin/hr/executive + AUDIT_READ 双闸）还原明文并写 `AUDIT_REVEAL` 二次审计 |

## 五、残留低危 / 遗留（不阻塞验收，建议排期）

1. **[低] 2FA 短期放行标记 `2fa_ok:{userId}` 未绑定会话**：现无消费方；若未来敏感操作中间件读取需改为 `2fa_ok:{userId}:{jti}`。
2. **[低] employee.service / onboarding decrypt 硬编码 keyVersion=1**：主密钥轮转到 v2 后读取打码会失败 fallback（建议 keyVersion 读字段配置或统一入口）。
3. **[低] encryptedField.decryptBatch 审计 fire-and-forget（`.catch(()=>{})`）**：极端下审计可丢；批量解密建议改为批量写审计。
4. **[运维] dev ENCRYPTION_KEY 默认 `'a'*64`**：仅限 dev；staging/prod 必须注入真实 64hex key（docker-compose 已 required，部署时人工核对）。
5. **[运维] .env.production CORS_ORIGIN=http://localhost**：上线前需按真实前端域名修改。
6. **[文档] `POST /audit-logs/:id/reveal` 前端未接**：audit-masking.md §6.2 的"申请查看明文"按钮尚未实现（本期补了后端契约与实现）。
7. **历史审计明文行未回改**：按 audit-masking §7.1 自生效日起新写入加密；历史行若需查阅走 reveal/导出审批流（已按不可信处理）。
