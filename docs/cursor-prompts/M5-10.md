## 二、关键设计

1. **Actor 语义**：
   - C7/C8 原生支持 `actorId='SYSTEM'`（审计 actorType=SYSTEM、userId=null）→ 直接传 `'SYSTEM'`
   - C4/C6 的 `created_by_id` / `created_by` 为**必填 uuid FK**（无 SYSTEM 分支）→ 传 **system 服务账号**
     （`users.username='system'`，seed 新增，随机密码不可登录；缺失时 fallback admin）
2. **幂等**：`upsertJobScheduler(jobSchedulerId 稳定)` 重复启动/注册不重复入队；业务级幂等
   （同 period 批次 73402 / 同季度结算单 73607 / 无已发提成 73606 → skipped 不重试轰炸）。
3. **开关**：每个任务运行前查 `configs salary.scheduler.*`（seed 新增 5 项；缺失视为启用，便于故障时一键关闭）。
4. **Worker**：每队列 concurrency=1（防并行重入）、attempts=2 + exponential backoff（沿用 M0.5-2 通知队列模式）。
5. **BullMQ v6 API**：用 `queue.upsertJobScheduler`（v6 已移除 `add({repeat})` 旧写法）。

## 四、遗留 / 运维说明

1. **system 用户与 scheduler.* configs 仅在新库 seed 生效**；现有 dev/预发库需重跑 seed（或手工 upsert）——
   未 seed 时任务经 admin fallback 运行（可接受，建议上线前 seed）。
2. **C4 自动月结前提**：createPayrollRun 强校验员工档案/薪酬方案/社保登记/绩效等级齐备，
   缺任一整批失败进 failed 队列（attempts=2）。上线前确保上月员工数据完整。
3. **AI 摘要任务**每日对已定稿无摘要批次调用 LLM（有成本）；provider 未配真 key 时是 mock，无成本。
   生产建议 LLM_PROVIDER 配真实 key 后观察 AI 调用监控成本。
4. dev 下 worker 随 server 启动即连 Redis（复用 notification worker 既有模式）；本地无 Redis 时 server 启动失败属预期（与现状一致）。
