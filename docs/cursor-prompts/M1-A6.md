### 任务 4: offboarding.service.ts（约 700 行）
**业务函数**（A6 特有）：
- `createOffboarding(input, createdBy)` — 提交离职申请
  - 校验 employee.status='active'（probation 不能直接离职，要先转正，71404）
  - 校验 employee 无 active 离职记录（71405）
  - 从 configs.offboarding.handover_template 自动生成 5 个 handover_tasks
  - 状态：→ handover_pending
- `getOffboardingById(id)` / `listOffboardings({ companyId, status, page, pageSize })`
- `confirmHandover(id, operatorId)` — 部门负责人确认交接
  - 校验所有 handover_tasks 全部 done（否则 71505）
  - 状态：handover_pending → submitted
  - 触发 approval.submitApproval
- `submitOffboarding(id, operatorId)` — 提交审批（handover_pending → submitted 内部调用）
- `confirmOffboarding(id, approvalResult, operatorId)` — 审批通过回调
  - prisma.employee.update({ status: 'resigned', resignationDate: lastWorkingDate })
  - 触发账号禁用（按 configs.offboarding.account_disable_strategy）
  - 调 archiveEmployee(employeeId)（内部函数，写 audit + configs.archive.years 计算保留期）
  - 状态：submitted → approved
- `disableUserAccount(employeeId)` — 内部函数，prisma.user.update({ status: 'disabled' })
- `issueCertificate(id, operatorId)` — 生成离职证明
  - 校验 status='approved' 且 certificateIssued=false（否则 71507）
  - 一期：mock PDF 生成（HTML 模板 + 水印，写入 filePath，URL 存 certificateUrl）
  - 编号规则：configs.offboarding.certificate_number_format（fallback 'OFFBOARD-{year}{seq:4}'）
  - 状态：approved → certificate_issued
  - 调 notification.sendNotification(bypassTemplate: { channel: 'email', subject: '离职证明', content: '...' })
- `cancelOffboarding(id, reason, operatorId)` — 撤回
  - handover_pending / submitted 状态可取消
  - approved 状态 → 71506（不可取消，留 A5 调动或更后期处理）
- `listUpcomingResignations(days)` — 给 BullMQ 调用（账号禁用前 N 天提醒）
- `checkArchiveAccess(employeeId, userRoles, resignationDate)` — 离职 1 年后档案访问 RBAC 校验

**集成调用**（**零重写 / 零 import 跨 service**）：
- approval.submitApproval / withdraw
- notification.sendNotification（bypassTemplate fallback，参考 A4 模式）
- configService.getValue
- auditService.auditLog
- prisma.employee.update / prisma.user.update / prisma.employeeSalaryHistory.create（直接操作）
- prisma.offboardingRecord.create / findFirst（直接操作）
