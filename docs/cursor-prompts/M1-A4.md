### 任务 1: 更新 Prisma schema（+ 1 张表 + 索引）

**新增模型**（参考 A3 风格）：

```prisma
// ==================== M1-A4 转正流程 ====================
// 状态机：draft → submitted → approved / rejected / cancelled
// 关联 employee（A2 已有）+ approval_instance（M0.5-1 已有）
model RegularizationRecord {
  id            String   @id @default(uuid()) @db.Uuid
  // 关联员工（必须是 probation 状态）
  employeeId    String   @map("employee_id") @db.Uuid
  // 试用期
  hireDate      DateTime @map("hire_date") @db.Date // 从 employee.hireDate 复制
  probationEndDate DateTime @map("probation_end_date") @db.Date // 试用期到期日
  // 申请内容
  appliedAt     DateTime @default(now()) @map("applied_at") @db.Timestamptz(6)
  // 自评 / 上级评 / HR 评（提交时可填）
  selfEvaluation String? @map("self_evaluation") @db.Text
  managerEvaluation String? @map("manager_evaluation") @db.Text
  hrEvaluation  String?  @map("hr_evaluation") @db.Text
  // 绩效评分（0-100，可选）
  performanceScore Int? @map("performance_score")
  // 转正后薪资（如有调整）
  newBaseSalary Decimal? @map("new_base_salary") @db.Decimal(10, 2)
  newPerformanceSalary Decimal? @map("new_performance_salary") @db.Decimal(10, 2)
  newTotalSalary Decimal? @map("new_total_salary") @db.Decimal(10, 2)
  // 状态机
  status        String   @default("draft") @db.VarChar(20)
  // draft / submitted / approved / rejected / cancelled
  // 审批流（M0.5-1）
  approvalInstanceId String? @unique @map("approval_instance_id") @db.Uuid
  // 审批结果
  approvedAt    DateTime? @map("approved_at") @db.Timestamptz(6)
  approvedBy    String?  @map("approved_by") @db.Uuid
  rejectedAt    DateTime? @map("rejected_at") @db.Timestamptz(6)
  rejectedBy    String?  @map("rejected_by") @db.Uuid
  rejectedReason String? @map("rejected_reason") @db.Text
  // 元数据
  createdBy     String?  @map("created_by") @db.Uuid
  createdAt     DateTime @default(now()) @map("created_at") @db.Timestamptz(6)
  updatedAt     DateTime @updatedAt @map("updated_at") @db.Timestamptz(6)
  cancelledAt   DateTime? @map("cancelled_at") @db.Timestamptz(6)
  cancelledBy   String?  @map("cancelled_by") @db.Uuid
  cancelledReason String? @map("cancelled_reason") @db.Text

  @@unique([employeeId]) // 一个员工只能有一条 active 转正记录（除 cancelled）
  @@index([status, probationEndDate])
  @@index([companyId]) // 注意：需要 JOIN employees 取 companyId，或冗余字段
  @@map("regularization_records")
}
```

- 如果不想加 `@@unique([employeeId])`（因为取消后可重新提交），改为部分索引或
  在 service 层校验（status != 'cancelled' 时唯一）
- **不修改 A1+A2+A3 任何已有表**
- Company/Department/Employee 不加 regularizationRecords 关系字段（避免改

### 任务 4: 写 regularization.service.ts（核心业务）

**新建**：server/src/services/regularization.service.ts（约 400-500 行）

**业务函数**：
- `createRegularization(input, createdBy)`：HR 代员工创建转正草稿
  - 校验 employee 存在且 status='probation'（否则 71404）
  - 校验 employee 没有 active 转正记录（status != 'cancelled'，否则 71405）
  - 计算 probationEndDate = hireDate + configs.probation.months
  - 审计：action=CREATE, resourceType=RegularizationRecord
- `getRegularizationById(id)`：单查（含 employee 关联信息）
- `listRegularizations({ companyId, departmentId, status, page, pageSize })`：列表
- `updateRegularization(id, input)`：更新（仅 draft 状态可改）
  - 状态校验：非 draft → 71403
  - 审计：action=UPDATE
- `submitRegularization(id, operatorId)`：提交审批
  - 状态校验：仅 draft 可提交
  - 调 approval.submitApproval({ flowKey: configs.regularization.approval_flow_key
    （fallback 'regularization:regularization_approval'），businessType: 'regularization',
    businessId: id, initiatorId: operatorId,
    title: `${employee.name} 转正审批`,
    data: { employeeId, currentStatus, probationEndDate, performanceScore, newBaseSalary } })
  - 状态：draft → submitted
  - 审计：action=UPDATE
- `confirmRegularization(id, approvalResult, operatorId)`：审批通过回调（系统内部）
  - 调 prisma.employee.update({ where: { id: employeeId }, data: { status: 'active' } })
  - 如有 newBaseSalary：调 prisma.employeeSalaryHistory.create({ data: {
    employeeId, effectiveDate: nextMonthStart,
    baseSalary, performanceSalary, totalSalary,
    changeType: 'regularization', reason, operatorId } })
  - 调 notification.sendNotification(templateKey='regularization_confirmed')
  - 状态：submitted → approved
  - 审计：action=APPROVE
- `rejectRegularization(id, reason, operatorId)`：审批拒绝回调
  - 状态：submitted → rejected
  - rejectedReason / rejectedAt / rejectedBy 写入
  - 调 notification.sendNotification(templateKey='regularization_rejected')
  - 审计：action=REJECT
- `cancelRegularization(id, reason, operatorId)`：撤回/取消
  - draft 状态：直接 cancelled
  - submitted 状态：调 approval.withdraw(approvalInstanceId) → cancelled
  - approved 状态：→ 71408（已批准不可取消；如需"撤销转正"留 A6 离职处理）
  - 审计：action=CANCEL
- `listUpcomingRegularizations(days)`：**给 BullMQ 调用**
  返回 N 天内试用期到期的员工列表（status=probation + probationEndDate 在 [now, now+days]）

**内部辅助**（不 export）：
- `getProbationEndDate(hireDate)`：hireDate + configs.probation.months 计算
- `getNextMonthStart()`：当前日期的次月 1 号（薪资生效用）
- `validateEmployeeProbation(employeeId)`：员工必须 status='probation'
- `validateNoActiveRegularization(employeeId)`：无 active 转正记录
