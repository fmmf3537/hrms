### 4.1 子任务 7.1：加班费占比预警（overtime_ratio.service.ts）

**0 新表**（仅读 C4 `payslips` + `payslip_items` + B4 `overtime_requests`）

**Service 函数**：
- `scanOvertimeRatioAlerts(actorId, period)` — 扫描指定 period（YYYY-MM）的加班费占比，**返回**新创建的 `HrCostAlert[]`
- `getOvertimeRatioThreshold()` — 内部辅助函数，读 `salary.hr_attrition.overtime_ratio_threshold` + `salary.cost_alert.overtime_ratio.severity_critical`

**算法**（V1.2 §四.8 + §三.5.2）：
1. 校验 period 格式（YYYY-MM）→ 否则抛 73707
2. 读 `salary.hr_attrition.overtime_ratio_threshold`（默认 0.20）+ `salary.cost_alert.overtime_ratio.severity_critical`（默认 0.30）→ 缺失或格式错抛 73708
3. 查 C4 `payslips`（period 过滤，**仅查 status='approved' 或 'locked'**，避免 draft 误报）
4. prisma 关联 `payslip_items`（**itemType='earning_overtime'** 过滤），累加 `amount` = 加班费
5. 累加 `payslip.totalGross` = 工资总额（含 base + performance + overtime + allowance + commission + bonus）
6. 计算 `overtimeRatio = sum(overtimeAmount) / sum(totalGross)`
7. **按部门聚合**（`prisma.employee.groupBy({ by: ['departmentId'] })`），每个部门独立计算
8. **判断预警**：
   - `overtimeRatio > severity_critical (0.30)` → `severity='critical'`
   - `overtimeRatio > threshold (0.20)` 且 `<= 0.30` → `severity='warning'`
   - 否则不创建预警
9. 事务：create `HrCostAlert`（`alertType='overtime_ratio'`, `period`, `departmentId`, `actualValue`, `threshold`, `severity`, `status='active'`, `scanAt=now()`）
10. 触发通知：调 `notificationService.sendNotification({ type: 'email', template: 'overtime_ratio_alert', data: {...}, bypassTemplate: true })`
11. 写 audit（COST_ALERT_SCAN，actorType='USER'，details: { alertType, period, alertCount, threshold, severity }）
12. **去重**：同一 (period, departmentId, alertType) 已有 active 状态预警不重复创建

**完整 schema + JSDoc + 错误码触发条件 + 测试断言**：见 §5.2。
