## 4. 实施任务

### 4.1 子任务 5.1：产品字典 + 提成比例配置（performance_sales_products）

**表**：`performance_sales_products`
- 字段：id (uuid) / code (string unique) / name (string) / category (enum) / baseRate (decimal) / description (text nullable) / status (enum) / createdById (uuid FK) / createdAt / updatedAt
- enum：`category` ∈ {`product`, `service`, `training`}；`status` ∈ {`active`, `archived`}
- 约束：baseRate ∈ (0, 0.5]（configs.performance.sales.commission.default_rate 默认 0.05，**最大 50%**）
- index：`@@unique([code])` + `@@index([category, status])`

**Service 函数**：
- `createProduct(actorId, input)` — 创建产品（code 唯一 + category 白名单 + baseRate 范围）
- `listProducts(actorId, filter)` — 列表（category/status 过滤 + 分页）
- `updateProduct(actorId, id, input)` — 更新（仅 active 可改 name/description/baseRate/category；code 不可改）
- `archiveProduct(actorId, id)` — 归档（active → archived）

**Controller 函数**：
- `POST /sales/products` → 调 createProduct
- `GET /sales/products` → 调 listProducts
- `PATCH /sales/products/:id` → 调 updateProduct

**完整 schema + JSDoc + 错误码触发条件 + 测试断言**：见 §5.1。

### 4.2 子任务 5.2：回款登记 + 财务确认（performance_sales_payments）

**表**：`performance_sales_payments`
- 字段：id (uuid) / employeeId (uuid FK) / productId (uuid FK) / customerName (string) / amount (decimal) / paymentDate (date) / period (string YYYY-MM) / status (enum) / confirmedById (uuid FK nullable) / confirmedAt (datetime nullable) / remark (text nullable) / createdById (uuid FK) / createdAt / updatedAt
- enum：`status` ∈ {`draft`, `confirmed`, `cancelled`}
- 约束：amount > 0；confirmed 状态必须有 confirmedById + confirmedAt
- index：`@@index([employeeId, status])` + `@@index([productId, status])` + `@@index([status, paymentDate])` + `@@index([period, status])`

**Service 函数**：
- `createPayment(actorId, input)` — 销售登记回款（status=draft，校验 employee 是销售岗）
- `listPayments(actorId, filter)` — 列表（employeeId/productId/status/period 过滤 + 分页）
- `confirmPayment(actorId, id, input)` — 财务确认到账（status=draft → confirmed + 写 confirmedBy + confirmedAt + 触发 calculateCommission）
- `cancelPayment(actorId, id, reason)` — 取消（draft 状态可取消，confirmed 状态不可取消）

**Controller 函数**：
- `POST /sales/payments` → 调 createPayment
- `GET /sales/payments` → 调 listPayments
- `PATCH /sales/payments/:id/confirm` → 调 confirmPayment

**完整 schema + JSDoc + 错误码触发条件 + 测试断言**：见 §5.2。

### 4.3 子任务 5.3：提成计算 + 发放（performance_sales_commissions）

**表**：`performance_sales_commissions`
- 字段：id (uuid) / employeeId (uuid FK) / paymentId (uuid FK unique) / productId (uuid FK) / baseAmount (decimal) / commissionRate (decimal) / targetBonusRate (decimal default 0) / finalAmount (decimal) / period (string YYYY-MM) / status (enum) / calculatedBy (string) / calculatedAt (datetime) / paidAt (datetime nullable) / remark (text nullable) / createdAt / updatedAt
- enum：`status` ∈ {`calculated`, `paid`, `cancelled`}
- 约束：`@@unique([paymentId])`（同一 payment 仅 1 条 commission）；`finalAmount = baseAmount × (commissionRate + targetBonusRate)`（目标完成率上浮后）
- index：`@@index([employeeId, status])` + `@@index([status, period])` + `@@index([period, status])`

**Service 函数**：
- `calculateCommission(actorId, paymentId)` — 单条计算（被 confirmPayment 触发，也可手动调用）
- `listCommissions(actorId, filter)` — 列表（employeeId/productId/status/period 过滤 + 分页）
- `payoutCommission(actorId, id)` — 标记发放（calculated → paid，写 paidAt + audit）

**提成计算公式**（V1.2 §二.5.4 + §二.5.4 末尾）：

```ts
// 步骤 1：基础提成
baseAmount = payment.amount
commissionRate = product.baseRate  // 产品/服务/培训 差异化
// 注：rate_tiers 仅作为提示默认值，D5 实际用 product.baseRate（V1.2 §二.5.4 第二条）

// 步骤 2：目标完成率上浮
```
