## 1. 任务 ID + 目标

### 1.1 任务 ID

**M5-2-D4**（M5 绩效前端 · 销售提成切片）

### 1.2 任务目标

为绩效模块新增「销售提成」前端：产品/项目字典与提成比例配置、回款登记与财务确认、提成计算与列表。消费后端 M3-D5 已就绪的 8 个端点（`/api/performance/sales/*`），0 新增后端端点。

**业务背景**（PRD §二.5.4）：提成 = 回款金额 × 提成比例；比例按产品差异化（无人机整机/服务/培训）；**财务确认到账后才触发提成核算**；提成随月度工资发放（与 M4 薪酬的联动不在本切片，本切片只做绩效侧）。

### 1.3 端点清单（8 个，全部已实读 `server/src/routes/performance.ts` 核实）

| # | Method | Path | 权限点 | 说明 |
|---|---|---|---|---|
| 1 | POST | `/api/performance/sales/products` | `performance:sales:product:write` | 新建产品（201 返回单条） |
| 2 | GET | `/api/performance/sales/products` | `performance:sales:product:read` | 产品列表（分页） |
| 3 | PATCH | `/api/performance/sales/products/:id` | `performance:sales:product:write` | 更新产品（含归档） |
| 4 | POST | `/api/performance/sales/payments` | `performance:sales:payment:write` | 登记回款（201 返回单条） |
| 5 | GET | `/api/performance/sales/payments` | `performance:sales:payment:read` | 回款列表（分页） |
| 6 | PATCH | `/api/performance/sales/payments/:id/confirm` | `performance:sales:payment:confirm` | 财务确认到账 |
| 7 | GET | `/api/performance/sales/commissions` | `performance:sales:commission:read` | 提成列表（分页） |
| 8 | POST | `/api/performance/sales/commissions/calculate` | `performance:sales:commission:write` | 按 paymentId 触发提成计算（201 返回单条） |

**请求体 schema**（已实读 zod 定义）：

- 新建产品：`{ code(1-50), name(1-200), category: 'product'|'service'|'training', baseRate?: number, description?: ≤2000 }`
- 更新产品：name/category/baseRate/description 全可选
- 产品列表 query：`category?/status?: active|archived/page/pageSize(≤100)`
- 登记回款：`{ employeeId(uuid), productId(uuid), customerName(1-200), amount(number), paymentDate(string), period?: 'YYYY-MM', remark?: ≤2000 }`
- 回款列表 query：`employeeId?/productId?/status?: draft|confirmed|cancelled/period?/page/pageSize`
- 确认回款：`{ remark?: ≤2000 }`（body 可为空对象）
- 提成列表 query：`employeeId?/productId?/status?: calculated|paid|cancelled/period?/page/pageSize`
- 提成计算：`{ paymentId(uuid) }`

## 5. 关键决策点（详尽）

### 5.1 响应结构确认（动笔前先实读 3 个 service 源码，把结论写进交付报告）

- 3 个 list → `{ items, total, page, pageSize }`（已初核，需你复核 items 字段集）
- create/update/confirm/calculate → 单条实体
- **列表接口不 include employee/product**（已实读确认）→ 名称展示靠前端联查

### 5.2 提成比例的百分比转换

`baseRate` / `commissionRate` / `targetBonusRate` 是 Decimal(5,4) 小数。**前端统一约定：存储/传输 = 小数，展示/输入 = 百分比**。转换函数写在 types 文件或视图内（`rateToPercent` / `percentToRate`），并在测试中断言（如 0.05 ↔ 5）。注意浮点精度：用 `Math.round(x * 10000) / 100` 类处理。

### 5.3 员工/产品名称联查

沿用 D3 PayoutList 模式：`listEmployees` + `listProducts` 拉全量做 id→名称映射表。已知限制（员工 >200 分页查不全）沿用 D3 报告口径，写入已知问题即可，不另行解决。

### 5.4 不做清单

- 无回款取消端点 → 不做取消按钮
- 无提成发放/取消端点 → 不做（发放走 M4 薪酬联动，非本切片）
- 销售目标管理与目标完成率上浮（后端 `targetBonusRate` 固定 0，留联调）→ 前端展示该字段即可，不做配置 UI
- 不做 ESS 视角（employee 仅产品字典只读，无「我的提成」——提成明细员工在工资条查看，属薪酬域）
