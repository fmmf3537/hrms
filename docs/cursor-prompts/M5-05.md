## 3. 必读约束

1. **实读先行**：写场景前实读 `server/src/routes/` 确认 5 个目标 GET 端点的真实路径与参数（下列路径仅为线索，以代码为准）：员工列表、考勤记录列表、请假列表、算薪 Run 列表、绩效周期列表。分页参数名/默认值以服务实现为准。
2. **token 前置 + 复用**：`auth-setup.mjs` 流程 = 若 `loadtest/.auth/admin-token.json` 存在且 JWT `exp*1000 - 30s > now`（base64url 解码 payload 解析，参照 `e2e/global-setup.ts`）→ 直接复用；否则登录获取并落盘。**压测全程只有这一个请求碰登录接口**。
3. **token 注入**：processor.mjs 的 artillery processor 函数在每个 VU 的 beforeScenario 从 token 文件读 token 塞进 `context.vars`，场景 header 引用 `Authorization: Bearer {{ token }}`。
4. **只读场景**：5 个 GET 场景按权重混合；任何场景不得产生写操作。
5. **429 监控**：若压测中业务接口出现 429/5xx，在报告中单独统计说明（可能是全局限流中间件），不要通过下调并发硬压过去。
