# M5-05 Fix 1：Artillery payload CSV 解析器与 JSON token 文件格式冲突

> **关联任务**：M5-05 并发压测
> **Fix 轮次**：fix1（第 1 次修订）
> **根因**：artillery 的 `payload` 配置默认使用 CSV 解析器读取数据文件，`.auth/admin-token.json` 是 JSON 格式，CSV 解析器遇到 JSON 中的引号报 `Invalid Opening Quote`

---

## 问题描述（上一轮停滞根因）

上一轮执行在 `artillery run loadtest/load-test.yml` 步骤无限循环失败，错误信息：

```
Error: Invalid Opening Quote: a quote is found inside a field at line 2
```

opencode 尝试了多种修复（改 YAML 格式、换路径、检查 BOM、查找源码），均未能定位根因。

**实际根因**：artillery 的 `config.payload` 功能**默认按 CSV 格式解析数据文件**。当 `path` 指向一个 JSON 文件（`admin-token.json`）时，CSV 解析器无法正确处理 JSON 中的引号，导致报错。

## 修复要求

### 1. 禁止使用 artillery `payload` 功能读取 JSON token

`load-test.yml` 中**不得**出现 `config.payload` 段。改为以下方式注入 token：

### 2. processor.mjs 直接读取 JSON token 文件

`processor.mjs` 的 `beforeScenario` 钩子中，直接用 Node.js `fs.readFileSync` 读取 `loadtest/.auth/admin-token.json`，解析 JSON 后将 `token` 注入 `context.vars`。

**正确模板**：

```javascript
// M5-05: 并发压测 | HRMS | 2026-09-02
import { readFileSync } from 'fs';
import { join, dirname } from 'path';
import { fileURLToPath } from 'url';

const __dirname = dirname(fileURLToPath(import.meta.url));
const tokenPath = join(__dirname, '.auth', 'admin-token.json');

export function beforeScenario(context, ee, next) {
  try {
    const raw = readFileSync(tokenPath, 'utf8');
    const parsed = JSON.parse(raw);
    // admin-token.json 结构: { token: "...", exp: 123456 }
    context.vars.token = parsed.token;
  } catch (err) {
    ee.emit('error', `Token read failed: ${err.message}`);
  }
  return next();
}
```

### 3. load-test.yml 移除 payload 段，header 保持 `{{ token }}`

```yaml
config:
  target: http://localhost:3000
  processor: ./processor.mjs
  # ❌ 禁止这里出现 payload 段
  defaults:
    headers:
      Authorization: "Bearer {{ token }}"
      Accept: "application/json"
```

### 4. auth-setup.mjs 落盘格式

确保 `auth-setup.mjs` 写入的 `loadtest/.auth/admin-token.json` 格式为：

```json
{"token":"eyJ...","exp":1788339486}
```

（即 `{ token: string, exp: number }`），供 `processor.mjs` 直接 `JSON.parse` 读取。

### 5. 其他文件保持不变

- `auth-setup.mjs` 的 token 前置复用逻辑（§3.2）不变
- `README.md` 不变
- 压测场景、phases、权重、断言均不变
- 达标线（100VU/120s/错误率<1%/p95<2000ms）不变

## 执行步骤

1. 按上述模板重写 `loadtest/processor.mjs`（若已存在则覆盖）
2. 修改 `loadtest/load-test.yml`：删除 `config.payload` 段，确认 `processor: ./processor.mjs` 和 `defaults.headers.Authorization` 正确
3. 运行 `node loadtest/auth-setup.mjs` 获取 token
4. 运行 `pnpm test:load`（即 `node loadtest/auth-setup.mjs && artillery run loadtest/load-test.yml`）
5. 如不达标，允许 1-2 次调优重跑
6. 按 M5-05 原提示词 §7.2 模板输出完整交付报告（含「红线自检」）
