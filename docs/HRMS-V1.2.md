## 一、概述

### 1.1 项目背景

西安辰航卓越科技有限公司（以下简称"辰航卓越"）当前员工规模约 40 人，业务涵盖无人机/低空安全方向，下属多家子公司（含北京平谷低空安全研究院），员工分布于西安、北京、四川多地。现有员工管理方式以 Excel + 纸质档案为主，存在以下痛点：

- 员工档案分散、更新滞后，入转调离流程无标准化留痕
- 考勤数据手工汇总，外勤/驻场人员打卡无统一方案
- 薪酬核算依赖人工，与考勤、绩效数据未联动，差错率高
- 绩效考核流程（员工自评→上级评分→部门校准→HR汇总→总经理审批）尚无系统承载
- 正式员工与实习生/顾问/劳务人员混管，薪酬与劳务费结算通道未分离
- 西安/北京/四川三地社保公积金政策差异需人工匹配

### 1.2 项目目标

建设一套自研的 AI 原生员工管理系统（HRMS），覆盖"人—考勤—算薪—绩效"核心数据闭环，并嵌入 AI 能力提升 HR 效率。具体目标：

1. 实现集团—法人—部门三级组织架构与员工全生命周期（入转调离）线上化管理
2. 实现正式员工与实习生/顾问/劳务人员的分类管理与差异化结算
3. 实现固定办公 + 外勤 GPS + 项目驻场的多模式考勤
4. 实现薪酬自动核算（联动考勤 + 绩效），支持西安/北京/四川多地社保公积金
5. 实现 KPI+OKR 混合绩效考核流程，绩效系数可后台配置
6. 嵌入 4 个点状 AI 能力（OCR / 算薪校验 / 智能问答 / 绩效评分建议），提升 HR 效率 ≥40%
7. 支持云端部署（阿里云/腾讯云），并发能力 ≥100 用户
8. 预留二期扩展能力：培训发展、员工自助、招聘系统对接、电子签

### 1.3 项目范围

| 阶段 | 范围 | 说明 |
|---|---|---|
| **一期** | M0 脚手架 + M0.5 基础设施与 AI 底座 + M1 组织人事 + M2 考勤假勤 + M3 绩效管理 + M4 薪酬核算 + M5 联调上线 | 核心数据闭环 + 嵌入式 AI 能力，本文档重点 |

### 1.5 行业趋势与 AI 原生策略（2026）

- **AI 原生**：AI 简历解析、AI 面试、AI 员工助手、AI 排班、对话式 BI、AI 算薪校验
- **一体化**：招聘→入职→人事→绩效→薪酬全链路数据打通
- **角色化工作台**：HR / 员工 / 经理 / 高管 / 候选人 五类角色差异化门户
- **合规优先**：电子签、个税直连、多地社保、劳动法规库、审计追踪

**辰航 AI 原生策略**：不追求"AI 大而全"，聚焦 4 个高 ROI 的点状能力（§三.3），用 M0.5 搭底座，业务模块按需调用。

### 1.6 选型决策

综合公司规模（40 人）、保密资质要求、业务特殊性（无人机/低空安全）、自研可控性需求，决定采用**自研内部系统**路线，不采购商业 SaaS。一期聚焦核心四模块 + 嵌入式 AI，避免大而全。

## 二、业务需求

### 2.1 组织与用户分析

#### 2.1.1 组织架构

- **集团层**：辰航卓越（母公司）
- **法人层**：西安辰航卓越科技有限公司、北京平谷低空安全研究院、四川相关子公司
- **部门层**：产教服务中心、人力资源、财务、技术、生产、销售、职能等
- **岗位层**：高管 / 部门负责人 / 技术 / 生产 / 销售 / 职能

#### 2.1.2 用户角色

| 角色 | 人数估计 | 核心诉求 |
|---|---|---|
| 系统管理员 | 1-2 | 组织架构维护、权限分配、系数配置、数据备份 |
| HR | 2-3 | 入转调离办理、考勤核对、薪酬核算、绩效汇总、报表导出 |
| 部门负责人 | 5-8 | 团队考勤查看、绩效评分与校准、请假/加班审批 |
| 高管（董事长/总经理） | 3-5 | 绩效终评、薪酬审批、人力成本报表、AI 智能问答 |
| 正式员工 | ~30 | 打卡、请假、查工资条、绩效自评、AI 智能问答 |
| 实习生/顾问/劳务 | ~5-10 | 打卡、查劳务费结算单 |

#### 2.1.3 用工形式分类

| 用工形式 | 合同类型 | 结算通道 | 是否缴社保 | 个税方式 |
|---|---|---|---|---|
| 正式员工 | 劳动合同 | 薪酬模块 | 是 | 工资薪金所得 |
| **研究院聘用人员**（新增） | 聘用合同 | 薪酬模块 | **是（机关事业单位养老保险，独立配置）** | 工资薪金所得 |
| 实习生 | 实习协议 | 劳务费结算 | ⚠️ 见下 | 劳务报酬所得 |
| 顾问 | 顾问协议 | 劳务费结算 | 否 | 劳务报酬所得 |
| 劳务人员 | 劳务合同 | 劳务费结算 | ⚠️ 见下 | 劳务报酬所得 |

**用工形式判定风险注**（HR / 法务必读）：
1. **研究院聘用人员**：北京平谷低空安全研究院属研究机构，员工走**机关事业单位养老保险**方案（费率、缴费基数上限与企业社保完全不同），必须在 `configs.social_insurance.research_institute.*` 单独配置；合同模板使用"聘用合同"而非"劳动合同"。
2. **实习生**：月龄 ≥ 8 且年满 16 周岁、接受单位管理并支付报酬，可能构成事实劳动关系（依据劳社部发〔2005〕12 号《关于确立劳动关系有关事项的通知》），单位应缴社保。系统在"实习生"类型提交时弹窗提示 HR 二次确认"是否构成事实劳动关系"，若"是"则引导切换为"正式员工"。
3. **劳务人员**：本系统定义的"劳务人员"是**与本公司直接签约的临时用工**（如短期项目工）；**劳务派遣**人员由派遣公司缴社保，与本表"劳务人员"是两种关系，须在 `employee.contract_type` 单独标记以区分。

### 2.2 模块 A：组织人事

#### 2.2.1 组织架构管理

- 架构层级：集团 → 法人（公司）→ 一级部门 → 二级部门（**最多 4 级**）
- 部门属性：部门编码（唯一）、部门名称、上级部门、负责人、编制数、成本中心、生效日期
- 调整规则：部门合并/撤销需 **HR + 总经理双审批**（走 M0.5 审批流基础设施）；调整历史保留 5 年
- 编制预警：在岗数 > 编制数 × 1.1 时触发预警（系统消息 + 邮件）

#### 2.2.2 员工档案

8 类约 60 字段：

| 类别 | 关键字段 | 必填 | 敏感 |
|---|---|---|---|
| 基础信息 | 工号、姓名、性别、身份证、出生日期、籍贯、民族 | 是 | 身份证加密 |
| 联系信息 | 手机、邮箱、紧急联系人、现居住地 | 手机必填 | 否 |
| 教育经历 | 学历、学位、毕业院校、专业、毕业时间 | 最高学历必填 | 否 |
| 工作经历 | 历史雇主、岗位、任职时间 | 否 | 否 |
| 合同信息 | 合同类型、签订/到期日期、续签记录 | 是 | 否 |
| 资质证书 | 无人机执照、其他资质、有效期 | 否 | 否 |
| 银行卡 | 开户行、卡号 | 正式员工必填 | 卡号加密 |
| 社保公积金 | 参保地、基数、参保起止 | 正式员工必填 | 基数加密 |

**关键交互**：
- 身份证号自动校验合法性，自动计算出生日期与性别
- **AI OCR 自动填充**（M1 嵌入）：员工上传证件/银行卡/证书照片后自动识别填入对应字段 —— 接口见 [`api-spec.md`](./api-spec.md) §4.5 `/ai/ocr`，数据流见 [`flow-diagrams.md`](./flow-diagrams.md) §1.1 入职流程
- 合同到期前 **30/15/7 天**三级预警（系统消息 + 邮件，走 M0.5 通知基础设施）
- 资质证书到期前 60 天预警（无人机执照年审）
- 员工信息修改支持员工自助提交 + HR 审批（二期）

#### 2.2.3 入转调离流程

**入职流程**（走审批流）：
1. HR 发起入职登记（可对接招聘系统 offer 数据，二期）
2. 系统自动生成工号（规则：法人代码 + 入职年份 + 4 位流水号，配置化）
  - **不复用**：离职员工工号永久保留（参见 `configs.employee_no.reuse_after_resign`）
  - **自然年度重置**：每年 1 月从 `0001` 开始（参见 `configs.employee_no.yearly_reset`）
  - **DB 唯一约束**：`employees` 表 `(company_id, EXTRACT(year FROM hire_date), seq)` 组合索引
  - **并发安全**：使用 PostgreSQL `SEQUENCE` 对象（按 `(company_id, year)` 组合），事务内申请流水号
3. AI OCR 收集资料（身份证、学历证书、银行卡、社保转移单、保密协议）
4. 合同签订（电子签，二期；一期线下扫描上传）
5. 开通系统账号 + 分配角色
6. 入职引导清单（设备发放、工位安排、导师分配、培训安排）

**转正流程**：
- 试用期到期前 15 天自动触发提醒（HR + 部门负责人 + 员工）
- 员工提交转正申请 → 上级评估 → HR 审批 → 总经理审批
- 转正后薪资自动按正式薪资标准核算（从次月生效）

**调动流程**：
- 调出部门负责人 + 调入部门负责人 + HR + 总经理逐级审批
- 调动生效日自动更新：部门、岗位、汇报关系、薪酬标准、权限
- 调动类型：平调 / 晋升 / 降职（晋升/降职需附带薪资变更审批）

**离职流程**：
1. 员工提交离职申请（或公司发起）
2. 工作交接清单（部门负责人确认）
3. 设备归还 + 系统账号禁用 + 门禁权限回收
4. 薪资结算（含未发工资 + 补偿金 + 调休折现）
5. 社保减员 + 公积金封存
6. **离职证明生成**（《劳动合同法》§50 法定义务，A6 切片提供；带电子签章或防伪水印 PDF，可邮件推送 / 下载）
7. 档案归档（保留 5 年）

**A6 切片同步落地的账号生命周期 SOP**（V1.2 新增）：
- 离职生效日 0 点自动禁用账号
- 离职 1 年后档案访问权限：仅 admin + 原 HR 可见（其他角色 403）
- 离职后员工邮箱保留 3 个月后归档（不删除历史邮件，便于法务追溯）
- 在职 / 收入 / 实习证明推到二期**ESS 证明开具模块**

### 2.3 模块 B：考勤假勤

#### 2.3.1 打卡管理

**打卡方式**：

| 方式 | 适用场景 | 校验规则 |
|---|---|---|
| WiFi 打卡 | 固定办公（西安/北京/四川办公室） | 连接指定 WiFi SSID 才能打卡 |
| GPS 打卡 | 外勤/项目驻场 | 定位精度 ≤100m，需上传位置描述 |
| 考勤机（得力 e+） | 固定办公 | 一期：按得力 e+ 导出格式手工导入打卡数据；二期：接入得力开放 API 自动同步 |
| 补卡 | 漏打卡 | 每月限 3 次，需上级审批 |

**打卡规则**：
- 标准工时：9:00-18:00，午休 12:00-13:30，弹性 30 分钟
- 综合工时（生产/外场）：按月/季为周期综合计算工时
- 不定时工时（高管/销售）：不打卡，仅记录出差/外勤
- 迟到：9:00-9:30 打卡为迟到；>9:30 为缺卡
- 早退：17:30 前打卡
- 缺卡：当日无任何打卡记录

**考勤数据源策略（得力 e+ 对接）**：
- 现状：公司使用得力云考勤机，打卡数据上云至得力 e+ 平台
- **一期（方案 B）**：HRMS 先不直连得力 API，由行政从得力 e+ App 导出打卡记录（Excel），通过 HRMS「考勤数据导入」功能入库存档
- 二期：接入得力 e+ 开放平台（v2-api.delicloud.com），自动同步部门/员工与打卡数据
- 架构约束：员工表、部门表必须预留 `external_id`（对应得力 `employee_ext_id` / `department_ext_id`）
- 得力适配器作为一期可选尾巴：若接口授权提前就绪，可与手工导入并存

#### 2.3.2 排班管理

- 班次定义：班次名称、上下班时间、午休时长、有效日期
- 排班粒度：按日 / 按周模板 / 按月模板
- 排班冲突检测：连续工作 ≤6 天，最小休息间隔 ≥12 小时
- 调班申请：员工发起 → 双方同意 → 上级审批

#### 2.3.3 假勤管理

**假期类型与额度**：

| 假期类型 | 额度规则 | 薪资规则 |
|---|---|---|
| 年假 | 工龄 1-10 年 5 天，10-20 年 10 天，>20 年 15 天 | 带薪 |
| 病假 | 按医疗期规定 | 按当地最低工资 80% 计 |
| 事假 | 不限 | 无薪 |
| 调休 | 加班 1:1 累计，有效期 6 个月 | 带薪 |
| 婚假 | 3 天 + 各地奖励婚假 | 带薪 |
| 产假/陪产假 | 按各地政策 | 带薪 |
| 丧假 | 1-3 天（直系亲属） | 带薪 |

**请假审批流**（走 M0.5 审批流基础设施）：
- ≤3 天：员工 → 直属上级 → HR 备案
- >3 天：员工 → 直属上级 → 部门负责人 → HR → 总经理
- 年假/调休：系统自动校验余额，余额不足禁止提交

**加班管理**：
- 加班申请：事前申请，注明加班事由与预计时长
- 加班补偿：加班费（按法定标准）或调休（1:1），员工自选
- 加班上限：每日 ≤3 小时，每月 ≤36 小时（劳动法）

**出差管理**：
- 出差申请：出差地点、起止日期、出差事由、关联项目
- 出差期间打卡：GPS 外勤打卡
- 差旅补助：按出差天数 × 标准自动计算（按城市/职级差异化），进入薪酬模块

#### 2.3.4 考勤汇总

- 月度汇总：每月 1 日自动生成上月考勤报表
- 员工确认：每月 3 日前员工在线确认，逾期默认确认
- HR 锁定：每月 5 日 HR 锁定考勤数据，进入算薪流程
- 考勤报表：出勤天数 / 迟到早退次数 / 请假时长 / 加班时长 / 出差天数

### 2.4 模块 C：薪酬核算

#### 2.4.1 薪酬体系配置

**薪级薪档**：
- 按岗位序列定义薪级表：高管（M1-M4）/ 部门负责人（M5-M6）/ 技术（T1-T6）/ 生产（P1-P6）/ 销售（S1-S6）/ 职能（A1-A6）
- 每个薪级含 5-7 个薪档，对应基本工资 + 绩效工资基数

**固浮比配置**：

| 序列 | 固定:浮动 | 说明 |
|---|---|---|
| 高管 | 60:40 | 年薪制 |
| 部门负责人 | 70:30 | 月薪制 |
| 技术 | 80:20 | 月薪制 |
| 生产 | 75:25 | 月薪制 |
| 职能 | 85:15 | 月薪制 |
| 销售 | — | 底薪 + 回款提成 |

#### 2.4.2 自动核算

**月度核算公式**：

```
应发工资 = 基本工资
        + 绩效工资（绩效工资基数 × 绩效系数）
        + 保密补贴（固定，按职级）
        + 勤补贴（按出勤天数 × 标准）
        + 项目奖金（按项目触发）
        + 销售提成（按回款金额 × 提成比例）
        + 年终奖（12 月单独发放）
        + 差旅补助（出差天数 × 标准）
        + 加班费（加班时长 × 加班费标准）

应扣款项 = 社保（个人部分）
        + 公积金（个人部分）
        + 个税（累计预扣）
        + 事假扣款（事假天数 × 日工资）
        + 病假扣款（病假天数 × 日工资 × 20%）
        + 迟到早退扣款（按次 × 标准）

实发工资 = 应发工资 - 应扣款项
```

**核算触发**：
- 每月 5 日 HR 锁定考勤后自动触发核算
- 核算异常自动提示（如绩效系数缺失、社保基数未配置）
- 支持手动重算（需二次确认 + 操作日志）
- **AI 算薪校验摘要**（M4 嵌入）：核算完成后，AI 对比上月自动生成"异常项摘要"（如"张三本月工资比上月少 1500 元，原因是事假 2 天 + 绩效 B→C"）

#### 2.4.3 社保公积金

**多地方案**（**示例值基于 2024 年 7 月数据**，具体由 `configs.social_insurance.city` 配置表维护，禁止硬编码；季度复核更新）：

| 城市 | 养老保险 单位/个人 | 医疗保险 单位/个人 | 失业保险 单位/个人 | 工伤 单位/个人 | 生育 | 公积金 单位/个人 | 调基月 |
|---|---|---|---|---|---|---|---|
| 西安 | 16% / 8% | 8% / 2% | 0.7% / 0.3% | 0.2%-1.9% / — | 并入医保 | 5%-12% / 5%-12% | 7 月 |
| 北京 | 16% / 8% | **9.0% + 1%（大病）/ 2%** | 0.5% / 0.5% | 0.2%-1.9% / — | 并入医保 | 5%-12% / 5%-12% | 7 月 |
| 四川 | 16% / 8% | 8.5% / 2% | 0.6% / 0.4% | 0.2%-1.9% / — | 并入医保 | 5%-12% / 5%-12% | 7 月 |

**表头说明**：
- 工伤单位/个人：`0.2%-1.9%` 是按行业基准费率（不固定），`/` 后 `—` 表示**个人不缴**
- 生育：目前全国 31 省市**全部并入医疗保险**（不单独征缴），不展示具体数字
- 公积金：单位/个人 5%-12% 区间，各地可在 5%-12% 内选档（详见 `configs.social_insurance.<city>.housing_fund_rate`）
- 调基月：通常是 7 月（一年一次），但个别城市有差异（上海 4 月、深圳 7 月、成都 7 月、北京 7 月、西安 7 月），按 HR 实际配置

注：单位比例 / 个人比例；比例为示例，实际按各地最新政策配置

- 系统按员工参保地自动匹配方案
- **调基月配置化**：每个城市调基月走 `configs.social_insurance.<city>.base_adjustment_month`（如西安 7 月、北京 7 月、上海 4 月、深圳 7 月、成都 7 月；个别城市有差异，须按 HR 实际配置）
- 支持社保增减员台账导出（用于社保局申报）

#### 2.4.4 个税

**工资薪金（累计预扣法）**：
- 起征点：5000 元/月
- 专项附加扣除（6 项 + 婴幼儿照护，共 7 项）：
 - 子女教育：2000 元/月（每个子女）
 - **3 岁以下婴幼儿照护：2000 元/月（每个婴幼儿，2023 年起新增）**
 - 赡养老人：3000 元/月（独生子女）/ 兄弟姊妹分摊 ≤ 1500 元/月（非独生分摊）
 - 房贷利息：1000 元/月（首套房贷款）
 - 房租：1500 元/月（北上广深）/ 1100 元/月（其他城市）
 - 继续教育：400 元/月（学历继续教育 ≤ 48 个月）/ 3600 元/年（职业资格）
 - 大病医疗：年度 8 万元限额（据实扣除）
- **个人养老金扣除**（2022 年起新增）：12000 元/年
- 税率表：3% / 10% / 20% / 25% / 30% / 35% / 45%（7 级超额累进）

**年终奖**：单独计税或并入综合所得，员工自选（系统默认单独计税，12 月可切换）。
- ⚠️ **政策有效期注**：依据《财政部 税务总局关于延续实施全年一次性奖金等个人所得税优惠政策的公告》（财税〔2023〕30 号），单独计税政策有效期至 **2027 年 12 月 31 日**；2028 年起若未续期，HR / 系统须自动切换为"并入综合所得"。建议在 M3 切片加"政策有效性预警"，由 `configs.tax.year_end_bonus_policy` 控制。

**劳务报酬**：
- 预扣率：≤4000 元 800 元起征；>4000 元 20% 起征
- 税率：20% / 30% / 40%（3 级超额累进）

#### 2.4.5 劳务费结算（独立通道）

- 适用对象：实习生 / 顾问 / 劳务人员
- 结算方式：按次 / 按月 / 按项目
- 计税：按劳务报酬所得
- 发放：生成劳务费结算单，财务审批后发放
- 凭证：自动生成记账凭证（借：管理费用-劳务费，贷：银行存款 / 应交税费-个税）

#### 2.4.6 工资条与发放

- 电子工资条：每月 10 日前推送（邮件 + 系统内查看，走 M0.5 通知基础设施）
- 工资条内容：应发合计 / 各项扣款 / 实发金额 / 个税明细
- 工资表导出：Excel / PDF（含汇总表 + 明细表）
- 银行代发文件：工行 / 建行 / 招行格式
- 薪酬审批流：HR 核算 → 财务复核 → 总经理审批 → 发放

### 2.5 模块 D：绩效管理

#### 2.5.1 考核体系配置

**考核模式**：KPI + OKR 混合
- KPI：定量指标（如销售额、项目交付率、bug 率）
- OKR：定性目标（如"提升团队协作效率"）
- 各序列指标类型统一框架：公司级指标 → 部门级指标 → 个人指标

**考核周期**：月度考核 + 季度兑现

**考核等级与系数**（后台可配置）：

| 等级 | 系数（默认） | 比例建议 | 说明 |
|---|---|---|---|
| S | 1.5 | ≤10% | 卓越 |
| A | 1.2 | ≤20% | 优秀 |
| B | 1.0 | ~50% | 合格 |
| C | 0.8 | ~15% | 待改进 |
| D | 0.5 | ≤5% | 不合格 |

注：头部限高不强制末位，比例仅供参考，季度校准会最终确认

#### 2.5.2 考核流程

**月度考核流程**：
1. 每月 25 日：员工提交自评（KPI 完成度 + OKR 进展）
2. 每月 27 日：直属上级评分
3. 每月 28 日：部门负责人校准
4. 每月 29 日：HR 汇总
5. 每月 30 日：总经理审批
6. 次月 1 日：结果归档，绩效系数联动薪酬

**AI 绩效评分建议**（M3 嵌入）：
- 直属上级评分环节，AI 基于员工本月自评 + 历史绩效 + 考勤 + 项目交付数据，**生成 3 条评分建议**（带依据引用）
- 上级可在 AI 建议基础上调整，确认最终分数
- AI 不替代人决策，只加速决策

**季度校准会**：
- 每季度末月 30 日召开
- 部门负责人 + HR + 总经理参加
- 校准各部门 S/A/B/C/D 比例，避免过松或过紧

#### 2.5.3 绩效兑现（双轨制，后台可切换）

**模式一（默认）：系数直接乘绩效工资基数**
```
绩效工资 = 绩效工资基数 × 绩效系数
```

**模式二：部门绩效池二次分配**
```
部门绩效池 = 部门绩效工资总额 × 部门绩效系数
个人绩效工资 = 部门绩效池 × (个人绩效系数 / 部门成员系数总和)
```

**预支机制**：
- 季度前两个月按系数 1.0 预支
- 季度末按实际系数清算（多退少补）

#### 2.5.4 销售提成

**提成规则**：
- 提成 = 回款金额 × 提成比例
- 提成比例按产品/项目差异化配置（如无人机整机 5%、服务 8%、培训 3%）
- 回款确认：财务确认到账后触发提成核算
- 提成发放：随月度工资一并发放

**销售目标**：
- 季度/年度回款目标
- 新客户开发目标
- 目标完成率与提成比例挂钩（如完成率 >120% 提成比例上浮 20%）

#### 2.5.5 绩效结果应用

- **调薪**：年度调薪参考近 4 个季度绩效（S/A 优先）
- **晋升**：晋升答辩需提供近 2 年绩效记录（至少 2 个 A 或 1 个 S）
- **淘汰**：连续 2 个季度 D 档触发 PIP（绩效改进计划），PIP 期 3 个月，仍未达标启动离职流程
- **培训**：C/D 档员工自动纳入下季度培训计划

### 2.6 系统管理

#### 2.6.1 用户权限

- **RBAC 模型**：用户 → 角色 → 权限 → 资源
- **数据权限**：HR 全员可见；部门负责人本部门可见；员工仅本人可见
- **敏感操作二次授权**：查看薪资、导出工资表需部门负责人 + HR 双授权
- **字段级加密**（M0.5 基础设施）：身份证、银行卡、社保基数、薪资字段 AES-256

#### 2.6.2 审批流配置（M0.5 新增基础设施）

- **可视化流程设计器**（拖拽配置）—— 二期
- M0.5 阶段先做**配置化 JSON 模板**（每类审批一份 JSON，支持条件分支）
- 支持条件分支（如请假 >3 天自动加总经理审批）
- 支持会签 / 或签 / 依次审批
- 支持审批超时自动提醒（24 小时未审批提醒，48 小时升级，走 M0.5 通知基础设施）

#### 2.6.3 系数配置

- 绩效系数：S/A/B/C/D 五档系数可调整
- 固浮比：按序列可调整
- 提成比例：按产品/项目可调整
- 差旅补助标准：按城市/职级可调整
- 所有调整留痕，**支持版本回溯**（配置表 + effective_from / effective_to 字段，详见 §三.5）

#### 2.6.4 数据字典

- 学历、民族、政治面貌、婚姻状况、假期类型、合同类型等基础数据维护
- 支持自定义扩展字段

#### 2.6.5 审计日志

- 记录所有关键操作：登录、查看、新增、修改、删除、导出、审批
- 日志字段：操作人、操作时间、操作类型、操作对象、操作前后值、IP 地址
- 日志保留 3 年，支持按人/按时间/按操作类型检索
- **审计范围定义**（V1.2 新增）：只审计"查看详情/查看个人档案/查看薪资"，**不审计"列表浏览"**（避免日志爆炸）
- **脱敏策略**（V1.2 新增）：`oldValue` / `newValue` JSON 字段中，金额字段保留分位精度，身份证/银行卡字段脱敏后存储（如 `110***********0023`）

### 3.1 技术栈

| 层 | 选型 | 说明 |
|---|---|---|
| 后端 | Node.js + Express + TypeScript + Prisma ORM | 与招聘系统一致 |

**代码范式统一**（V1.2 明确）：采用当前 HRMS 已落地的 **function 导出** 模式（`export function xxx() {}`），**不再沿用招聘系统的 class + 静态方法**。AI Coding Prompt 模板同步更新。

**数据库选型锁定**（V1.2 明确）：一期及二期均使用 PostgreSQL 15+，**不预留 MySQL 迁移能力**。理由：
- Prisma 已抽象数据访问层，理论上换数据源成本可控，但**实际换库的工作量不在 driver，而在 schema 差异、特性差异、运维工具链**（pgvector / PostgreSQL 扩展等）
- 业务规模 100 人以下，单库性能完全够用
- 团队只维护一套技术栈，比"兼容多数据库"更易做稳
- 如未来真有跨数据库需求，应通过**数据导出导入**而非"双数据库"实现

#### 3.3.3 共同技术底座（M0.5 阶段搭好）

- **LLM 网关**：统一封装 OpenAI / 国产模型（DeepSeek / 通义千问）调用，token 用量监控、限速、错误重试
- **向量库**：**pgvector**（PostgreSQL 内置扩展，避免引入外部依赖），用于 RAG 检索

#### 3.3.5 AI 能力验收标准

- OCR 准确率：身份证字段 ≥99.5%，银行卡 ≥99%，资质证书（手写）≥85%

- 绩效评分建议：上级采纳率 ≥50%，且采纳后 HR 复审无重大偏差

### 3.4 安全架构

#### 3.4.1 认证与授权

- **认证**：账号密码 + JWT access token（15min）+ refresh token（7d，已升级为 rotation + reuse 检测）
- **二次验证**（V1.2 新增）：登录后敏感操作（查看薪资 / 导出 / 修改权限）需短信/邮箱验证码
- **权限**：RBAC（角色-权限-资源三级），M0 已实现 requirePermission 中间件

#### 3.4.2 数据加密（M0.5 新增）

- **密码**：bcrypt 散列（已用 bcryptjs，cost=10，生产前换 `bcrypt` 或 `argon2`）
- **敏感字段**（身份证/银行卡/薪资）：AES-256-GCM 加密存储，密钥从环境变量加载 + KMS 托管
- **传输**：全站 HTTPS，TLS 1.2+
- **脱敏**：API 返回敏感字段时按角色脱敏（HR 全显、员工本人显、其他人 mask）

#### 3.4.3 审计

- 全部写操作 + 关键读操作写审计日志（详见 §2.6.5 范围定义）
- 日志不可篡改（追加写，定期归档到冷存储）
