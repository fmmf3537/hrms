# 西安辰航卓越科技有限公司  
员工管理系统需求文档

版本：V1.0 | 编制日期：2026-08-23 | 编制：WorkBuddy AI 协助

适用范围：西安辰航卓越科技有限公司及其下属子公司（含北京平谷低空安全研究院）

## 一、项目背景与目标

### 1.1 项目背景

西安辰航卓越科技有限公司（以下简称"辰航卓越"）当前员工规模约 40 人，业务涵盖无人机/低空安全方向，下属多家子公司（含北京平谷低空安全研究院），员工分布于西安、北京、四川多地。现有员工管理方式以 Excel + 纸质档案为主，存在以下痛点：

  * 员工档案分散、更新滞后，入转调离流程无标准化留痕
  * 考勤数据手工汇总，外勤/驻场人员打卡无统一方案
  * 薪酬核算依赖人工，与考勤、绩效数据未联动，差错率高
  * 绩效考核流程（员工自评→上级评分→部门校准→HR汇总→总经理审批）尚无系统承载
  * 正式员工与实习生/顾问/劳务人员混管，薪酬与劳务费结算通道未分离
  * 西安/北京/四川三地社保公积金政策差异需人工匹配



### 1.2 项目目标

建设一套自研的员工管理系统（HRMS），覆盖"人—考勤—算薪—绩效"核心数据闭环，并预留培训发展、员工自助、招聘系统对接的扩展能力。具体目标：

  1. 实现集团—法人—部门三级组织架构与员工全生命周期（入转调离）线上化管理
  2. 实现正式员工与实习生/顾问/劳务人员的分类管理与差异化结算
  3. 实现固定办公 + 外勤 GPS + 项目驻场的多模式考勤
  4. 实现薪酬自动核算（联动考勤 + 绩效），支持西安/北京/四川多地社保公积金
  5. 实现 KPI+OKR 混合绩效考核流程，绩效系数可后台配置
  6. 支持与现有招聘系统（PostgreSQL）数据对接
  7. 支持云端部署（阿里云/腾讯云），并发能力 ≥100 用户



### 1.3 项目范围

阶段| 范围| 说明  
---|---|---  
一期| A 组织人事 + B 考勤假勤 + C 薪酬核算 + D 绩效管理| 核心数据闭环，本需求文档重点  
二期| F 培训发展 + G 员工自助 + E 招聘系统接入| 体验增强与外部对接  
三期（预留）| AI 员工助手、人力 BI、继任梯队、OKR 对齐视图等| 视一期落地效果再启动

## 四、功能需求（一期核心模块）

### 4.1 模块 A：组织人事

#### 4.1.1 组织架构管理

  * 支持集团—法人—部门三级架构，可视化树形展示
  * 支持部门新增/合并/撤销/调整上级，调整历史可追溯
  * 支持编制管理（部门编制数 vs 在岗数，超编预警）
  * 支持职务体系（高管/部门负责人/主管/专员）与职位体系（技术/生产/销售/职能序列）



#### 4.1.2 员工档案

  * 基础信息：姓名、性别、身份证、出生日期、籍贯、民族、政治面貌、婚姻状况
  * 联系信息：手机、邮箱、紧急联系人、现居住地、户籍地
  * 教育经历：学历、学位、毕业院校、专业、毕业时间
  * 工作经历：历史雇主、岗位、任职时间、离职原因
  * 合同信息：合同类型、签订日期、到期日期、续签记录、电子合同附件
  * 资质证书：无人机执照（AOPA/UTC）、其他行业资质、有效期提醒
  * 银行卡信息：开户行、卡号（用于发薪）
  * 社保公积金：参保地、参保基数、参保起止日期
  * 照片与附件：证件照、身份证扫描件、学历学位证书、保密协议



#### 4.1.3 入转调离

  * **入职** ：offer 转入职 → 资料收集 → 合同签订 → 账号开通 → 设备发放 → 入职引导清单
  * **转正** ：试用期到期提醒 → 转正申请 → 上级评估 → HR 审批 → 薪资调整
  * **调动** ：调岗/调部门申请 → 双方负责人审批 → HR 备案 → 薪酬/权限变更
  * **离职** ：离职申请 → 工作交接清单 → 设备归还 → 薪资结算 → 社保减员 → 档案归档
  * 全流程支持自定义审批流（按用工形式/部门差异化配置）



#### 4.1.4 合同管理

  * 合同模板库（劳动合同/实习协议/顾问协议/劳务合同/保密协议）
  * 合同签订、续签、变更、终止全生命周期
  * 合同到期前 30/15/7 天三级预警
  * 电子签（二期接入）



### 4.2 模块 B：考勤假勤

#### 4.2.1 打卡管理

  * 多模式打卡：固定办公（WiFi/考勤机）+ 外勤 GPS 定位 + 项目驻场（指定打卡点）
  * 移动端打卡（HTML5 小程序/App，二期完善）
  * 打卡异常自动识别（迟到/早退/缺卡/外勤未签到）
  * 异常申诉流程：员工提交 → 上级审批 → HR 备案



#### 4.2.2 排班管理

  * 多工时制：标准工时（默认）/ 综合工时（生产/外场）/ 不定时工时（高管/销售）
  * 班次定义：早班/晚班/夜班/弹性班
  * 智能排班（一期简化：手动排班 + 模板复用）
  * 排班冲突检测（连续工作天数上限、最小休息间隔）



#### 4.2.3 假勤管理

  * 请假类型：年假/病假/事假/调休/婚假/产假/陪产假/丧假
  * 假期额度管理：年假按工龄自动累计、调休余额联动加班
  * 请假审批流：员工申请 → 上级审批 → HR 备案（>3 天加总经理审批）
  * 加班管理：加班申请 → 审批 → 加班费或调休二选一
  * 出差管理：出差申请 → 关联差旅补助标准 → 外勤打卡联动



#### 4.2.4 考勤汇总

  * 月度考勤报表（出勤天数/迟到早退次数/请假时长/加班时长）
  * 考勤确认：员工月度在线确认考勤结果，HR 锁定后进入算薪
  * 考勤数据实时同步至薪酬模块



### 4.3 模块 C：薪酬核算

#### 4.3.1 薪酬体系

  * 薪级薪档：按岗位序列定义薪级表（高管/部门负责人/技术/生产/销售/职能）
  * 固浮比配置：高管 60:40、部门负责人 70:30、技术 80:20、生产 75:25、职能 85:15
  * 薪酬结构项：基本工资 + 绩效工资 + 保密补贴 + 勤补贴 + 项目奖金 + 年终奖 + 差旅补助 + 销售提成



#### 4.3.2 自动核算

  * 月度核算流程：考勤数据 → 绩效系数 → 补贴/提成 → 社保公积金扣除 → 个税计算 → 实发工资
  * 绩效工资 = 绩效工资基数 × 绩效系数（默认 S=1.5 / A=1.2 / B=1.0 / C=0.8 / D=0.5，后台可配置）
  * 销售提成 = 回款金额 × 提成比例（按产品/项目差异化配置）
  * 项目奖金 = 按项目里程碑或回款比例触发，支持手动录入 + 审批
  * 年终奖 = 年度一次性发放，单独计税
  * 差旅补助 = 出差天数 × 标准（按城市/职级差异化）



#### 4.3.3 社保公积金

  * 多地社保方案：西安、北京、四川三地基数/比例模板
  * 按员工参保地自动匹配方案
  * 支持五险（养老/医疗/失业/工伤/生育）+ 公积金
  * 社保增减员台账



#### 4.3.4 个税

  * 工资薪金累计预扣法自动计算
  * 专项附加扣除（子女教育/赡养老人/房贷利息/房租/继续教育/大病医疗）
  * 年终奖单独计税/并入综合所得两种方式可选
  * 劳务报酬所得税自动计算（实习生/顾问/劳务人员）



#### 4.3.5 劳务费结算（独立通道）

  * 实习生/顾问/劳务人员不走薪酬模块，单独走劳务费结算
  * 支持按次/按月/按项目结算
  * 劳务报酬所得税自动计算（按次预扣 20%-40%）
  * 劳务费结算单生成与导出



#### 4.3.6 工资条与发放

  * 电子工资条（移动端查看，二期完善推送）
  * 工资表导出（Excel/PDF）
  * 银行代发文件生成（工行/建行/招行等主流银行格式）
  * 薪酬审批流：HR 核算 → 财务复核 → 总经理审批 → 发放



### 4.4 模块 D：绩效管理

#### 4.4.1 考核体系

  * 考核模式：KPI + OKR 混合，各序列指标类型统一框架
  * 考核周期：月度考核 + 季度兑现
  * 考核等级：S / A / B / C / D 五档
  * 绩效系数：S=1.5 / A=1.2 / B=1.0 / C=0.8 / D=0.5（**后台可配置** ）



#### 4.4.2 考核流程

  1. 员工自评（月度末提交）
  2. 直属上级评分
  3. 部门负责人校准
  4. HR 汇总
  5. 总经理审批
  6. 结果归档并联动薪酬



#### 4.4.3 绩效兑现（双轨制，后台可切换）

  * **模式一（默认）** ：绩效系数直接乘绩效工资基数
  * **模式二** ：部门绩效池二次分配（部门绩效总额 × 部门系数 → 部门内按个人绩效再分配）
  * 前两月按 1.0 预支，季度末按实际系数清算



#### 4.4.4 销售序列特殊规则

  * 销售人员不参与五档考核
  * 单独走回款提成通道：提成 = 回款金额 × 提成比例
  * 销售目标管理（季度/年度回款目标、新客户目标）



#### 4.4.5 绩效结果应用

  * 联动薪酬：绩效系数自动带入当月/当季核算
  * 调薪依据：年度调薪参考近 4 个季度绩效
  * 晋升依据：晋升答辩需提供近 2 年绩效记录
  * 淘汰预警：连续 2 个季度 D 档触发改进计划（PIP）



## 五、非功能需求

### 5.1 性能需求

  * 并发用户：≥100（按未来 200-300 人规模预留）
  * 页面响应：核心页面（员工列表/考勤/工资条）<2s
  * 月度算薪：200 人规模 <30s
  * 报表导出：单表 <10s



### 5.2 安全需求

  * 身份认证：账号密码 + 二次验证（短信/邮箱验证码）
  * 权限模型：RBAC（角色-权限-资源三级）
  * 数据加密：敏感字段（身份证、银行卡、薪资）AES-256 加密存储
  * 传输加密：全站 HTTPS
  * 审计日志：所有关键操作（查看/修改/导出薪资）留痕
  * 数据备份：每日全量 + 每小时增量



### 5.3 合规需求

  * 个人信息保护：符合《个人信息保护法》《数据安全法》
  * 保密资质：满足公司保密资质审查要求，薪资数据访问需二次授权
  * 劳动法合规：合同模板、考勤规则、加班管理符合最新劳动法



### 5.4 可用性需求

  * 系统可用性：≥99.5%（月度停机 <3.6 小时）
  * 浏览器兼容：Chrome / Edge / Firefox 最近两个版本
  * 移动端：H5 自适应（二期扩展为小程序/App）



### 5.5 可扩展性需求

  * 模块化架构：二期接入培训/员工自助/招聘系统时不需重构
  * 开放 API：预留 REST API 供第三方系统调用
  * 多数据库支持：当前 PostgreSQL，预留迁移 MySQL 能力

银行| 出| 工资代发| 银企直联（暂缓，先代发文件）  
  
## 八、数据需求

### 8.1 核心数据实体

  * 组织：法人、部门、岗位、职务
  * 人员：员工档案、合同、资质、家庭、教育、工作
  * 考勤：打卡记录、班次、排班、请假、加班、出差
  * 薪酬：薪级、工资单、补贴、提成、社保、公积金、个税
  * 绩效：考核方案、指标、评分、系数、校准
  * 流程：审批流、审批节点、审批记录
  * 系统：用户、角色、权限、菜单、日志、配置



### 8.2 数据保留策略

  * 在职员工：全量保留
  * 离职员工：档案保留 5 年（劳动法要求）
  * 考勤数据：保留 3 年
  * 薪酬数据：保留 10 年（税务要求）
  * 审计日志：保留 3 年



## 九、约束与假设

### 9.1 约束

  * 开发方式：Web Coding（Kimi Code 或同类 AI Coding 平台）
  * 开发周期：一期建议 3-4 个月（视 AI Coding 效率调整）
  * 预算：暂无上限约束，但优先复用招聘系统技术栈降低学习与维护成本
  * 团队：内部 IT + AI Coding 协作，无独立产品团队



### 9.2 假设

  * 用户已具备基础信息化素养，能使用 Web 系统
  * 公司网络环境稳定，云端部署可行
  * 招聘系统二期可开放对接 API
  * 现有《绩效考核与绩效工资方案》在一期上线前完成最终发布



## 十、风险与缓解

风险| 等级| 缓解措施  
---|---|---  
AI Coding 生成代码质量不稳定| 高| 严格代码评审 + 完整测试用例 + 小步迭代  
薪酬核算规则复杂易错| 高| 建立核算规则测试用例库 + 与手工核算并行 2-3 个月  
多地社保政策频繁调整| 中| 社保方案配置化 + 季度政策复核机制  
员工抵触新系统| 中| 充分的用户培训 + 上线初期 HR 一对一辅导  
数据迁移错误| 中| 迁移脚本双跑校验 + 历史数据备份  
保密数据泄露| 高| 字段级加密 + 访问审计 + 二次授权 + 内网部署选项  
  
## 十一、验收标准

### 11.1 功能验收

  * 组织架构可三级展示并支持调整
  * 完成 40 名员工档案迁移
  * 完成 1 个完整考勤月度周期（含外勤）
  * 完成 1 个完整薪酬核算周期（与手工核算结果一致率 ≥99.5%）
  * 完成 1 个完整绩效考核周期（自评→审批→联动薪酬）



### 11.2 性能验收

  * 100 并发压测通过
  * 核心页面响应 <2s
  * 月度算薪 <30s



### 11.3 安全验收

  * 通过渗透测试（无高危漏洞）
  * 敏感字段加密验证
  * 审计日志完整性验证
